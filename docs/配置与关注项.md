# 配置与关注项

> README 的展开篇：`profile` / `filter` / `budget` / `schedule` 这些键怎么写，「每一路独立」的关注项
> 到底覆盖了什么。实现见 [`intel/config.py`](../intel/config.py)、[`intel/topics.py`](../intel/topics.py)。

## 1 一份配置，一个入口

所有设置都在 `config.json` 里，`python main.py init` 生成，控制台和 `config set` 改的是同一份文件。

```bash
python main.py init                      # 已存在则跳过，不覆盖
python main.py config show               # 当前生效值（含默认值补齐后的结果）

python main.py config set \
  --focus "LLM agent,C++ 并发,逆向工程" \
  --avoid "加密货币,招聘广告" \
  --language zh \
  --instructions "偏工程细节，写清版本号和性能数字" \
  --tokens-run 60000 --tokens-day 200000 --on-exceed degrade \
  --mode times --times 08:30,21:00 \
  --weekdays 1,2,3,4,5 --active-hours 07:30-23:00 \
  --channels feishu --max-items 6
```

| 键 | 含义 |
|---|---|
| `profile.interests` / `avoid` | 关注范围与回避主题，同时驱动 AI 检索规划与判定 |
| `profile.custom_instructions` | 自由文本要求，作为「可信用户指令」注入判定 prompt |
| `profile.output_language` | `zh` / `en`，决定模型产出语言与渲染文案 |
| `budget.tokens_per_run` / `tokens_per_day` | 单轮 / 每日 token 上限，0 表示不限 |
| `budget.on_exceed` | `degrade`（降级规则）或 `stop`（中止本轮） |
| `schedule.mode` | `times`（固定时点）或 `interval`（活跃时段内每 N 分钟） |
| `schedule.weekdays` / `active_hours` | ISO 星期（1=周一）与活跃窗口，窗口外的时点跳过 |
| `channels.feishu.mode` | `webhook`（自定义机器人）或 `app`（企业自建应用） |
| `ai.enabled` / `triage` / `plan_queries` | 采集侧 AI 的三个开关 |
| `filter.silence.min_confidence` | 静默阈值：本轮最高置信低于它就只入库、不推送（可写在关注项里覆盖） |
| `output.creator.enabled` | 选题与脚本大纲开关（无模型时给规则大纲，不烧 token） |
| `channels.feishu.tasks.enabled` | 推送时顺带建飞书待办，需 app 模式 + `task:task:write` |
| `channels.dingtalk` | 钉钉群机器人；`webhook_env` / `secret_env` 填的是**环境变量名**，不是地址 |
| `schedule.briefing` | 晚间简报时间，如 `{"enabled": true, "time": "21:30"}` |

写盘路径只有一条：**校验 → 备份 → 原子写**。校验不过不落盘，前端拿到逐条错误；
旧文件保留最近 10 份（`config.json.bak-*`）。

## 2 关注项（每一路独立）

关注项是**订阅**，不是任务：没有「完成 / 负责人 / 进度」，只有「这一路盯什么、多久盯一次、怎么写」。

它只覆盖会影响这一路结果的字段（`profile` / `filter` / `sources` / `schedule` / `output`）。
渠道凭据、数据库、时区永远跟全局走——否则改一次 webhook 就要改 N 个文件。

```bash
python main.py topics add --id cpp-perf --name "C++ 性能" \
  --times 12:30 --focus "C++ 高性能与并发" \
  --instructions "只看可复现的 benchmark，观点文不要"

python main.py topics set --id cpp-perf --times 13:00 --disable
python main.py topics show cpp-perf
python main.py topics history cpp-perf --limit 10
python main.py topics rm --id cpp-perf           # 历史仍留在库里，可查
```

分区的意义：A 路把某个源的水位推进到 10:00，不会让 B 路漏掉 09:00 的条目；A 路认为无关丢掉的条目，
B 路仍然有权收一次。反过来，同一个 URL 跨关注项只推一次（全局幂等）。

## 3 非科技主题（金融 / 体育 / 医疗 / 消费）

关键词引擎与领域无关：同一套 `keywords` / `block_keywords` / `custom_instructions` 在财经、体育、
医疗语料上同样生效（见 [`tests/test_mixed_domains.py`](../tests/test_mixed_domains.py) 的 9 个主题）。
但换领域时有三件事必须一起改：

1. **采集源要换成该领域的**。默认 rss 列表全是科技源，只改关注项关键词会得到 0 条。
   实测可用的财经源：

   | 源 | RSS | 说明 |
   |---|---|---|
   | 华尔街见闻 | `https://dedicated.wallstreetcn.com/rss.xml` | 60 条/次，中文，最稳 |
   | CNBC 财经 | `https://www.cnbc.com/id/100003114/device/rss/rss.html` | 30 条，英文 |
   | WSJ 市场 | `https://feeds.a.dj.com/rss/RSSMarketsMain.xml` | 20 条，英文 |

2. **单源默认只取前 10 条**（`intel/sources/rss.py` 的 `limit` 默认值）。财经源一次给 60 条，
   想要全量就在 feed 上写 `"limit": 20`。

3. **中英混源必须配双语关键词**。关键词是字面子串匹配，中文词命中不了英文标题。实测同一批源，
   只给中文词时英文条目 0 入选；补上 `fed / rate / yield / gold / inflation` 后 CNBC 立刻有产出。
   加 `"lang": "en"` 可让该源渲染英文标签。

关键词是**或**关系，不是且。想做「AI + 金融」这种交集主题，靠关键词拼不出来（写 `["ai","金融"]`
等于两个都算命中），要用同时出现的短语（`量化私募`、`财报解读`），或在 `custom_instructions` 里写
「两个领域各看一半的不写」，交给判定模型筛。

## 4 把「人格模板」写成关注项

常见写法是给每个身份一段提示词（「你是我的 AI 资讯助手，我是…，相关性 0-1、重要性 0-10，
低于 0.6 不推，每天 5 条」）。这些要求都能落到字段上，不必塞进提示词：

| 模板里的说法 | 落到哪个字段 | 说明 |
|---|---|---|
| 我是…（角色） | `role` | 进判定 prompt 的「用户画像」 |
| 关注 A、B、C | `keywords` + `interests` | 前者决定召回，后者影响判定 |
| 不要 D | `block_keywords` + `avoid` | 前者硬砍（粗排），后者只降分 |
| 相关性 0-1 | `confidence`（0-1） | 四闸加权置信度，也是分流依据 |
| 重要性 0-10 | `score`（0-10） | 四闸加权分，用于排序与选题 |
| 低于 X 不推 | `filter.silence.min_confidence` | **可写在关注项里**，每个关注项一条线 |
| 高重要性即时推 | `filter.confidence.immediate` | 默认 0.80，关注项可覆盖 |
| 每天 N 条 | `filter.max_items_per_run` | 超出按分排序截断 |

实测（[`tests/test_personas.py`](../tests/test_personas.py)）：12 个人格里 10 个能直接跑通；
入门者（AIGC/办公）与投资人（融资/算力）召回为 0——不是提示词不清楚，而是默认科技源里没有这类内容。
